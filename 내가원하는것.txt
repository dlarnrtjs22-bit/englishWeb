영어 학습 웹 서비스 PRD + DB 스키마 + API 명세 + MVP 범위표
1. PRD 문서
1-1. 제품 개요
제품명(가칭)
NativeFlow
부제: 한국어 의미부터 시작하는 원어민식 영어 학습 플랫폼

제품 한 줄 설명
한국어 뜻과 뉘앙스를 먼저 보고, 영어 표현을 직접 떠올려 입력한 뒤, 발음·영작·AI 첨삭·간격 반복 복습으로 영어를 체화하는 구독형 학습 웹 서비스.

제품이 해결하려는 문제
기존 영어 학습 서비스는 대체로 다음 중 하나에 치우쳐 있다.

영어 단어를 단순 암기하게 만든다
시험 대비 중심이라 실제 원어민 감각과 거리가 있다
영어를 먼저 보여줘서 ‘회상 학습’이 약하다
복습 시스템은 있지만 문맥 적용이나 영작 피드백이 약하다
콘텐츠 구조가 산만해서 사용자가 꾸준히 이어가기 어렵다
이 제품은 이를 해결하기 위해
**“한국어 의미 → 영어 회상 → 정답 확인 → 영작 → AI 첨삭 → SRS 복습”**의 흐름을 핵심 학습 경험으로 제공한다.

1-2. 목표
비즈니스 목표
초기 목표는 한국인 대상 영어 학습 웹 서비스의 MVP를 빠르게 출시하고,
사용자의 학습 지속성과 반복 방문률을 높이는 것이다.

사용자 목표
사용자는 이 서비스를 통해 다음을 얻는다.

1-3. 타겟 사용자
1차 타겟
한국어를 모국어로 사용하는 영어 학습자

상세 사용자 유형
이 서비스는 다음 사용자에게 특히 잘 맞는다.

사용자 A: 실전 회화형 학습자
문법책보다 실제 원어민이 쓰는 표현을 익히고 싶은 사용자.
“doze off”, “pull off”, “figure out” 같은 표현을 상황감 있게 배우고 싶어 한다.

사용자 B: 뉴스/시사 영어 확장형 학습자
일상영어뿐 아니라 뉴스·정치·기술·과학 영어 표현을 체계적으로 배우고 싶은 사용자.

사용자 C: 꾸준히 복습해 실력으로 남기고 싶은 사용자
많이 보고 잊어버리는 패턴에서 벗어나, Anki 같은 간격 반복으로 장기 기억화를 원하는 사용자.

1-4. 제품 원칙
이 제품은 아래 원칙을 중심으로 설계한다.

원칙 1. 한국어 의미가 먼저다
학습의 출발점은 영어 단어 노출이 아니라 한국어 의미와 뉘앙스다.

원칙 2. 회상 중심 학습이어야 한다
정답을 먼저 보여주는 방식이 아니라, 사용자가 직접 떠올리게 해야 한다.

원칙 3. 단어보다 표현 단위에 집중한다
일상영어, 뉴스영어, 구동사, 상황 표현 등 실제 사용 단위 중심으로 구성한다.

원칙 4. 입력과 적용이 있어야 한다
정답 확인으로 끝나면 안 되고, 사용자가 직접 문장을 만들어봐야 한다.

원칙 5. 반복 복습은 자동화되어야 한다
사용자는 “무엇을 복습할지” 고민하지 않고, 시스템이 적절한 시점에 보여줘야 한다.

1-8. 기능 요구사항
인증
이메일 기반 회원가입/로그인 가능해야 한다.
세션이 유지되어야 한다.
인증되지 않은 사용자는 보호 페이지 접근이 불가해야 한다.
구독
사용자는 시리즈를 구독할 수 있어야 한다.
구독한 시리즈는 좌측 사이드바에 표시되어야 한다.
학습
학습 아이템은 기본적으로 한국어 뜻을 먼저 보여줘야 한다.
영어 정답은 제출 전까지 숨겨야 한다.
제출 후 정답, 발음, 부가정보가 보여야 한다.
학습 결과는 저장되어야 한다.
즐겨찾기
사용자는 학습 아이템을 즐겨찾기할 수 있어야 한다.
저장 목록에서 다시 접근 가능해야 한다.
영작/AI 첨삭
사용자는 표현을 이용한 영작을 제출할 수 있어야 한다.
AI는 문법/자연스러움/표현 적절성을 평가해야 한다.
피드백은 한국어 중심으로 보여주는 것이 좋다.
복습
사용자의 각 학습 아이템은 개별 복습 스케줄을 가져야 한다.
복습 버튼 결과에 따라 next_review_at이 갱신되어야 한다.
오늘 날짜 기준 due 아이템이 복습 큐에 표시되어야 한다.
관리자 기능
운영자는 시리즈/팩/아이템을 생성·수정·삭제할 수 있어야 한다.
공개 여부를 관리할 수 있어야 한다.
1-9. 비기능 요구사항
성능
대시보드 첫 로딩은 2초 이내가 목표다.
학습 카드 전환은 즉각적이어야 한다.
AI 첨삭은 최대 5~8초 이내 응답을 목표로 한다.
보안
비밀번호는 해시 저장해야 한다.
관리자/일반 사용자 권한 분리가 필요하다.
학습 이력 및 사용자 데이터는 사용자 본인만 접근 가능해야 한다.
확장성
source_language / target_language 구조로 다국어 확장 가능해야 한다.
콘텐츠 구조는 시리즈 > 팩 > 아이템 형태로 유지한다.
SRS 엔진은 사용자별 상태 기반이어야 한다.
운영성
관리자 없이 DB 직접 수정하는 구조는 피한다.
최소한 내부 어드민 페이지 또는 CSV import 구조가 필요하다.
1-10. 수용 기준
예시: 시리즈 구독
사용자가 구독 버튼을 누르면 성공 메시지가 뜬다
좌측 사이드바에 시리즈가 추가된다
대시보드 카드 상태가 구독중으로 바뀐다
예시: 학습 카드 제출
사용자가 영어를 입력하고 제출한다
정답 여부가 판별된다
정답이 공개된다
발음 버튼, 저장 버튼, 영작 영역이 노출된다
예시: SRS 저장
사용자가 Good을 누른다
현재 아이템의 next_review_at이 갱신된다
복습 큐에서 즉시 제거되거나 다음 상태로 이동한다
2. DB 스키마
아래는 PostgreSQL 기준의 추천 구조다.
실제 구현 시 Prisma 또는 Supabase 스키마로 변환해도 된다.

2-1. 핵심 테이블 구조
users
Copycreate table users (
  id uuid primary key default gen_random_uuid(),
  email varchar(255) unique not null,
  password_hash text,
  auth_provider varchar(50) default 'email',
  name varchar(100),
  role varchar(20) default 'user', -- user, admin
  native_language varchar(10) default 'ko',
  target_language varchar(10) default 'en',
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
series
Copycreate table series (
  id uuid primary key default gen_random_uuid(),
  title varchar(255) not null,
  slug varchar(255) unique not null,
  description text,
  thumbnail_url text,
  category varchar(100),
  source_language varchar(10) default 'ko',
  target_language varchar(10) default 'en',
  is_published boolean default false,
  created_by uuid references users(id),
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);
packs
Copycreate table packs (
  id uuid primary key default gen_random_uuid(),
  series_id uuid not null references series(id) on delete cascade,
  title varchar(255) not null,
  description text,
  order_index integer default 0,
  is_published boolean default false,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

4. SRS 로직 가이드
초기 MVP에서는 너무 복잡하게 가지 말고,
간단하지만 확장 가능한 규칙으로 시작하는 게 좋다.

4-1. 초기 상태
사용자가 어떤 아이템을 처음 학습 완료하면 review_schedules 레코드를 만든다.

기본값:

ease_factor = 2.5
interval_days = 0
repetition_count = 0
4-2. 버튼별 동작 예시
버튼	interval_days	repetition_count	ease_factor
again	1	max(0, current-1)	-0.20
hard	max(2, current interval)	+1	-0.10
good	current 기준 점진 증가	+1	유지
easy	current보다 더 크게 증가	+1	+0.10
4-3. MVP용 단순 계산 예시
좀 더 단순하게 시작하고 싶으면 이렇게 가도 된다.

첫 리뷰
again → 1일
hard → 2일
good → 3일
easy → 4일
두 번째 이후
again → 1일
hard → 현재 interval * 1.2
good → 현재 interval * 1.8
easy → 현재 interval * 2.5
실제 저장 시엔 반올림해서 integer day로 처리한다.

7. 개발팀 전달용 한 줄 요약
이 서비스는
**“한국어 뜻을 보고 영어를 회상하게 하는 학습 경험”**과
**“AI 영작 첨삭 + SRS 복습”**이 핵심인 구독형 영어 학습 플랫폼이다.

즉 MVP에서 절대 흔들리면 안 되는 우선순위는 아래 순서다.

콘텐츠 구조 → 구독 → 학습 카드 → 정답 체크 → AI 첨삭 → 복습 큐
